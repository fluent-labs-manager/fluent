# Сообщения коммитов

Используйте формат [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):

```text
<type>[(<scope>)][!]: <краткое описание>

[подробности]

[BREAKING CHANGE: описание несовместимого изменения]
```

`type` и описание обязательны. `scope`, `!`, подробности и footer необязательны. Scope может быть любым: например,
`auth`, `router`, `ui` или `api`. Описание пишите после двоеточия и пробела.

## Доступные типы

| Тип        | Когда использовать                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------ |
| `feat`     | Новая возможность интерфейса или приложения                                                                        |
| `fix`      | Исправление ошибки                                                                                                 |
| `docs`     | Документация                                                                                                       |
| `style`    | Форматирование без изменения поведения                                                                             |
| `refactor` | Изменение кода без новой возможности или исправления ошибки                                                        |
| `perf`     | Улучшение производительности                                                                                       |
| `test`     | Добавление или изменение тестов                                                                                    |
| `build`    | Сборка и зависимости                                                                                               |
| `ci`       | Конфигурация CI                                                                                                    |
| `chore`    | Прочие служебные задачи                                                                                            |
| `revert`   | Откат изменений                                                                                                    |
| `hope`     | Специально для [**Ulianaaaa**](https://github.com/Ulianaaaa), главного любителя коммитов вида `final final I hope` |

## Примеры

```text
feat(auth): add login form
fix(router): restore navigation after refresh
docs: describe local setup
feat(api)!: remove legacy response format
hope: final final I hope
```

Для несовместимого изменения добавьте `!` перед двоеточием и/или footer `BREAKING CHANGE: ...`. После `npm install`
Husky устанавливает Git hook `commit-msg`, который проверяет сообщение перед созданием коммита. Проверить сообщение
вручную можно командой `echo "feat(ui): add button" | npx commitlint`.
